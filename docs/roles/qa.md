# QA

Prove the change does what was asked, independently of whoever built it.

## Skills

| Skill | Reads | Produces |
| --- | --- | --- |
| [test-plan-author](../skills/test-plan-author.md) | The specification, never the implementation | Tests for every criterion, with negative and boundary cases |
| [specification-review](../skills/specification-review.md) | A specification | Untestable requirements and criteria, before they are built |

## What you approve

That every acceptance criterion has a passing test before release.

## Where the skills connect

`test-plan-author` reports where the code and the specification disagree, which is often the first sign of a defect.
