# Architect

Shape how the system fits together, and record why.

## Skills

| Skill | Reads | Produces |
| --- | --- | --- |
| [decision-record-author](../skills/decision-record-author.md) | The options and their trade-offs | A decision record that supersedes rather than rewrites |
| [specification-review](../skills/specification-review.md) | A specification, and the code it touches | Contradictions between the spec and the system |
| [backstage-catalog-builder](../skills/backstage-catalog-builder.md) | Repositories and their evidence | Catalog entities, ownership, and TechDocs, after confirmation |

## What you approve

Each decision's status, and the catalog model before it is registered.

## Where the skills connect

A decision record can cite the specification it serves; the catalog shows which team owns what the decision affects.
